# RelTwin：从共存的反向关系中学习查询对应的时间窗口

英文标题：**RelTwin: Learning Query-Specific Windows from Co-Occurring Inverse Relations**

目标会议：ICASSP 2027。作者：Zhicheng Tang、Yuehan Zhang；华中科技大学。2026-09-13 投稿打磨稿。核心改变：以“真实存在但不回答当前查询”的局部答案负例为主线，不再将 JS、SetPO 或动态边界分别宣传为已证实的核心提分模块。

## 摘要

音频时序定位不仅需要确认查询中的声音是否出现，还需要在多个真实事件窗口之间选出当前查询的答案。本文提出 RelTwin，在同一录音中构造同时成立的反向关系，使它们对应不同时间戳答案，并通过候选判别增强普通序列监督，推理不增加新模块。同环境、同更新步数的对照相较 SFT，在类别与原始录音来源隔离的合成开发集上提高 13.97 个 mIoU 点，在完整 SpotSound-Bench 上提高 1.02 点，两项分组置信区间均不跨零。候选监督模型的三种子平均 SpotSound mIoU 为 59.16，高于所引用此前主表最佳 57.9。增强项对照未确立交换正则或集合偏好继续训练的独立收益。结果支持面向查询的答案监督和双向正确定位诊断，自然关系泛化仍有待验证。

## 引言

音频时序定位要求根据自然语言查询，返回真正回答该查询的时间区间。文本到音频定位、音频片段检索以及 SpotSound 已建立语言描述与音频时间轴之间的对应，并改善不存在事件的识别。本文关注一个更具体的错误：声音确实存在，模型返回的窗口仍然答非所问。[Text-to-Audio Grounding](https://arxiv.org/abs/2102.11474)、[Language-based Audio Moment Retrieval](https://arxiv.org/abs/2409.15672)、[SpotSound](https://arxiv.org/html/2604.13023v2)。

考虑同一段录音中先出现“狗叫后响铃”，随后出现“响铃后狗叫”。两处包含相同声音类别，两条描述对整段录音都成立，但它们对应不同答案。把查询中的顺序反转，模型应当改变返回窗口；只识别狗叫和铃声并不足以决定答案。我们将这种返回真实事件、但选错查询指向的现象称为“查询—窗口绑定错误”。这与凭空预测不存在的事件不同，需要明确比较当前查询对应的正确窗口和混淆窗口。

已有研究已经处理音频组合关系。[T-CLAP](https://arxiv.org/html/2404.17806v1) 使用声音拼接、顺序反转描述和时间对比训练；[CompA](https://arxiv.org/html/2310.08753v3) 研究同事件不同顺序与属性的音频—描述匹配；[CoSTALA](https://arxiv.org/html/2608.24374v1) 进一步开展分层时空对齐。[SHINE](https://arxiv.org/abs/2407.05118) 在视频定位中使用组合难负查询。因此本文不将顺序反转、难负例或对比损失本身作为首次创新。我们的具体区别是：在相同整段音频内，让两条关系描述同时成立，却分别指向不同局部时间戳答案；负例是错误答案窗口，而不是对整段录音不成立的描述。

为此，我们构建 RelTwin 配对训练样本，复用同一对声音片段组成两个相反顺序的窗口，使每个关系查询同时面对正确和混淆候选。模型在正确时间戳序列监督之外，学习两候选的显式判别。推理阶段仍正常生成时间区间，不需要真实候选窗口，不增加候选判别器。本工作的贡献是局部答案负例的构造、它在生成式音频定位中的实现，以及对查询响应行为的受控验证，而不是一种新的通用对比公式。

实验围绕三个问题展开：相同关系数据上，候选监督是否优于普通 SFT；额外的交换正则和集合偏好训练是否必要；关系诊断的改善与公开定位分数是什么关系。分析同时检查“答案是否变化”和“变化后是否双向正确”，使正文的结论对应实际测量，不将完整系统的全部收益笼统归给某个模块。

## 方法

### 两条描述同时为真，但答案不同

给定音频 $x$、查询 $q$ 和真实区间集合 $G$，模型返回预测集合 $S$。RelTwin 使用 ESC-50 的两个声音片段 A、B，各重复两次，在同一录音中构造 $W_+=(A\to B)$ 与 $W_-=(B\to A)$。目标区间覆盖整段有序声音序列，而不是只覆盖其中一个声音。

| 查询 | $W_+$：A 后接 B | $W_-$：B 后接 A |
|---|---|---|
| $q_+$：A followed by B | 正确答案 | 真实存在，但不回答本查询 |
| $q_-$：B followed by A | 真实存在，但不回答本查询 | 正确答案 |

如果只问查询描述是否在整段音频中出现，两条查询的标签都是“存在”；这类标签本身没有给出表中的局部对应关系。这里讨论的是监督信息的区别，不是宣称全局预训练模型原则上无法完成定位。

每段音频提供“followed by”和“and then”两种模板、两个方向，共四条查询。另有类别查询，定位 A 或 B 的全部出现区间，用于普通定位回放。两个窗口的先后布局交替，减少固定选早段的捷径；片段复用控制了同一对查询中的声音来源和事件类别。构造仍包含重复片段、静音及与布局相关的间隔，不能据此宣称完全排除了合成捷径。

### 显式比较时间戳答案

令 $y(S)$ 为描述区间集合的时间戳序列，其平均 token 对数概率为

$$s_\theta(x,q,S)=\frac{1}{|y(S)|}\sum_t\log P_\theta(y_t\mid x,q,y_{<t}).$$

在候选 $C=(W_+,W_-)$ 上归一化得到

$$p_q(j)=\operatorname{softmax}_j\big(s_\theta(x,q,C_j)/\tau\big).$$

这是候选间的相对偏好，不是校准后的事件存在概率。配对候选损失为

$$\mathcal L_{cand}=-\tfrac12[\log p_{q_+}(1)+\log p_{q_-}(2)].$$

对单条查询，它就是常规二分类对比形式 $\log(1+\exp((s_--s_+)/\tau))$。作用是将正确区间与另一个真实存在的区间直接比较。完整简约目标为

$$\mathcal L=\mathcal L_{seq}+\lambda\mathcal L_{cand}+\beta\mathcal L_{replay}.$$

$\mathcal L_{seq}$ 监督两个正确答案，$\mathcal L_{replay}$ 保留普通类别定位信号。本文将该配置称为 **RelTwin-Cand**，对应现有代码的 `no_exchange`，不是重新调参得到的新模型。普通 SFT 使用完全相同的数据、正确答案和回放，但不使用候选判别损失。推理时，两者都正常生成时间区间。

### 更复杂的训练项是否必要

RBEE 在上述目标上增加 $\lambda\operatorname{JS}(p_{q_+},\Pi p_{q_-})$，$\Pi$ 交换两个候选的位置。这是候选概率的交换一致性正则，不是架构层面的严格等变。正确候选标签被完美拟合时，交换对应已经成立，JS 不再提供额外的最优标签。

SetPO 是后续 64 步训练，将候选扩展为两个正确/混淆窗口、各自扩张版本、两窗口并集及覆盖两窗口的大区间。软目标由 set-IoU 与对称最佳匹配区间 F1 的均值给出；该软 F1 不是一对一事件 F1。其恰当对照是从同一 parent 继续原 RBEE 目标 64 步，而不仅是未继续训练的 parent。本文将这些项目作为增强项检验，不预设它们带来独立收益。

### 同时检查定位重叠与关系选择

集合 IoU 按区间并集的时间长度计算：$\operatorname{IoU}_{set}(S,G)=|S\cap G|/|S\cup G|$。PairAcc 要求一对反向查询都达到正确目标 IoU≥0.5；JointPairAcc 进一步要求每条查询对正确目标的 IoU 严格高于对相反目标的 IoU。Swap error 表示至少一条查询不满足这种严格偏好，平局也计错。

一个直观反例是：两个目标互不重叠且等长，对两个查询都返回它们的并集，每条查询的 IoU 都为 0.5，能够通过 PairAcc，却没有区分查询关系。JointPairAcc 排除这一情况。它是适用于本任务的诊断组合，与 [Winoground](https://arxiv.org/abs/2204.03162) 的配对组合评测思想相关，不是新的通用指标，也不意味着标准 IoU 没有价值。

## 实验设置

适配训练使用 40 个 ESC-50 类别、256 段合成音频，生成 1,024 条关系查询、512 对训练样本和 512 条普通回放查询。另 10 个类别构成 80 段音频、320 条查询、160 对反向查询的开发集。适配训练与开发集的类别及原始 Freesound 录音 ID 均无交集；这不等于骨干预训练从未见过这些声音。该关系集已经参与开发，不是新的独立自然测试集。

所有训练从相同 SpotSound-A adapter 出发，骨干是 Audio Flamingo 3，更新 20,185,088 个 adapter 参数。SFT、Cand、RBEE 均训练 256 步，学习率 $5\times10^{-6}$，AdamW weight decay 为 0，梯度裁剪 1.0，$\tau=1$、$\lambda=1$、$\beta=0.5$。Cand 与 RBEE 使用 seed 0/1/2，并报告固定步数最终 checkpoint，不按种子挑选。

本轮新增的 SFT seed 0 与已有 Cand seed 0 在同一训练环境、源码、初始权重、数据顺序和配置下执行，改变训练目标及其实现。这是主要归因对照；等更新步数不等于等 FLOP。Cand 先对四个查询—答案组合无梯度评分，再重算加权梯度；SFT 仅对两个正确答案反向传播，两者都加回放。历史 SFT、RBEE、SetPO 也统一重新推理，但统一推理环境不能消除历史训练环境的混杂。

SetPO 与 RBEE 继续训练均从对应 parent 增加 64 步，学习率 $2\times10^{-6}$。SetPO 方法权重 0.5，目标温度 0.15，交换权重 1，回放权重 0.5，每四步使用一次集合回放。

SpotSound 使用全部 400 条查询、387 个音频文件；Clotho 系统参考使用全部 6,649 条。公开结果在项目开发中已被观察，不宣称整个研究过程从未查看测试集。所有比较先核对索引、查询、标注、音频、时长和逐条 IoU。20,000 次配对 bootstrap 将同一音频的反向查询及模板一起采样；关系集还按 39 个原始录音来源连通组重采样，最大组包含 18 段合成音频。区间条件于实际观察的种子，不代表训练种子总体，不消除开发选择偏差。

## 训练对照与结果分析

### 相同数据、相同环境：候选学习是否超出 SFT

同环境 SFT→Cand 的关系 mIoU 从 74.58 到 88.55，提高 **13.97 点**，来源组 95% CI 为 [9.84,17.51]；JointPairAcc 从 53.13 到 84.38，提高 **31.25 点**，CI 为 [22.35,40.50]；Swap error 从 40.00 降至 7.50。SpotSound 从 58.42 到 59.43，提高 **1.02 点**，音频组 CI 为 [0.23,1.81]。这些结果支持相对于当前固定配置 SFT 的收益，不能推广为已经排除全部 SFT 配置。公开集逐条胜/平/负为 92/239/69，其中两条下降至少 0.5 IoU，说明这是总体改善，不是每条样本都更好。

### 答案是否随查询正确变化

SFT 在 160 对反向查询中有 37 对返回完全相同的答案，涉及 22 个音频；Cand 仅剩 1 对。在这 37 对 SFT 同答案失败中，Cand 将 27 对修复为双向正确。放到全部关系对上，Cand 新修复 51 对，同时损失 1 对原本正确的样本。不能把同答案数量下降写成“关系错误清零”：Cand 仍有 25/160 对未达到 JointPairAcc。这些是同一开发集上的描述性分解，不是新增独立测试。

### 额外交换与集合目标是否必要

已完成三种子增强项对照如下，所有差值为目标减对照，单位为百分点。

| 比较 | 关系指标 | 增量 | 来源连通组 95% CI |
|---|---|---:|---|
| RBEE − Cand | mIoU | −0.27 | [−0.70,+0.06] |
| RBEE − Cand | JointPairAcc | +0.21 | [−0.88,+0.96] |
| SetPO − 等步数继续训练 | mIoU | +0.77 | [−0.05,+1.96] |
| SetPO − 等步数继续训练 | JointPairAcc | +1.04 | [−1.24,+4.76] |

Cand 与 RBEE 的关系 mIoU 均值为 87.05 和 86.78，JointPairAcc 为 81.46 和 81.67。JS 的两项增量区间均跨零。结果不证明两者等价，但不能据此将交换正则作为核心有效性主张；更简单的候选监督保留了现有开发集表现。

SetPO 比 parent 的关系 mIoU 高 3.04 点，继续原 RBEE 目标本身也提高 2.27 点。对齐额外训练步数后，SetPO 仅剩 0.77 点 mIoU 和 1.04 点 JointPairAcc，区间跨零；SpotSound 对应增量仅为 0.019 点。因此论文不能将“后续阶段更好”直接写成“集合偏好目标独立更好”。这些历史模型与新控制之间仍存在训练环境限制，使归因需要更加审慎。

## 局限与结论

RelTwin 目前验证的是简单顺序描述与合成窗口之间的绑定，不是任意自然关系推理。重复片段、固定表达、静音和布局相关间隔仍会产生合成捷径。类别和来源隔离、来源分组置信区间分别解决了特定的泄漏与依赖问题，不能消除所有分布偏差或开发选择。自然录音、重叠事件、复杂关系与长距离关系仍需要独立验证。

此外，同名历史 SFT 在当前推理下有 49/400 条 SpotSound 预测发生变化，输入 token 数全部相同。新稿使用统一重评对照，并增加同环境 SFT 桥接，不把这种执行差异包装为算法进展。同环境主对照仍只有一个种子，不能推广为全部 SFT 超参配置都已被排除。

本文针对“声音真实存在，但窗口答非所问”这一明确问题，构造同音频共存的反向关系，并将另一个真实窗口作为局部答案负例。方法使用简单的候选监督，配合正确序列学习与普通查询回放，推理不增加新模块。论文通过定位重叠、双向正确与查询响应行为共同检验这一训练设计，并将其证据与完整系统分数区分。核心贡献是具体监督设计及其行为证据，而不是新的通用对比原理。

## 作者备忘：名称与交付边界

RelTwin 是同音频逆关系配对构造；RelTwin-Cand 对应现有 `no_exchange` 配置；RBEE 是 Relation-Boundary Exchange Equivariance，候选训练加 JS 交换正则；SetPO 是 Setwise Preference Optimization，后续区间集合偏好训练；NOVA 是 Necessity-Oriented Verification over Audio，利用保留/移除区间后的响应进行候选验证；Boundary Utility 是局部边界编辑收益模型。名称不应替代有效性证据。

SpotSound-Bench 关注长音频中的短目标事件，当前运行 400 条查询；Clotho-Moment 是语言描述的音频片段检索，运行 6,649 条。前者提供本次训练方法的公开检查，后者当前仅提供 official 系统结果。RelTwin 开发集是自建诊断数据，不计入公开 benchmark 数量。
